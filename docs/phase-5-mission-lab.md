# Phase 5: Mission Lab Architecture

The Mission Lab integrates OrbitForge's scientific calculations, risk heuristics, and AI interpretation into a single unified analytical flow. 

## Architectural Philosophy
Mission Lab enforces a strict boundary between what the user provides, what the engine deterministically calculates, and how AI explains the results. The hierarchy is visually and technically enforced:

1. **Mission Configuration (Input)**: User-provided values (`altitude`, `inclination`, `duration`).
2. **Orbital Analysis (Model / Output)**: Deterministic two-body estimates generated by the scientific engine.
3. **Environmental Assessment (Output)**: Model-driven heuristics measuring radiation and drag exposure based on orbit parameters.
4. **Risk Assessment (Heuristic)**: Rule-based evaluation of environmental and orbital conditions resulting in a 0-100 score and risk factors.
5. **Mission Intelligence (AI Explanation)**: Secure, governed downstream ingestion of the previous models. AI acts as an interpreter, never as the source of truth.
6. **Decision Support (Action)**: The user applies their judgment based on the above pipeline, resulting in an audited mission state change.

## Workspace Isolation
All missions are stored securely under `workspaceId`. Analytical endpoints (`/api/analysis/:missionId`, `/api/intelligence/:missionId`) and CRUD operations (`/api/missions`) will reject cross-workspace access with a 403 Forbidden status.

## Frontend Error Handling
Unauthenticated access to the `Dashboard` or `Mission Lab` surfaces robust empty states rather than application crashes, prompting the user to authenticate before executing queries.
